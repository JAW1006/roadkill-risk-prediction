01 프로젝트 개요

도로를 잘라 위험도를 매기고, 담당자의 언어로 설명한다

도로망을 500m 구간으로 나눠 예측 단위를 만들고, 위험구간을 지도에서 탐색하며, 담당자가 구간을 고르면 자연어 브리핑과 챗봇 질의응답이 뒤따르는 흐름을 목표로 한다.

① 위험도 예측

도로 구간별 로드킬 위험도를 RandomForest → XGBoost → GNN 순으로 고도화하며 예측한다.

② GIS 대시보드

Streamlit + pydeck으로 위험구간을 지도 위에서 필터링하고 탐색할 수 있게 한다.

③ LLM 브리핑 · 챗봇

선택한 구간의 SHAP 근거를 Claude에 전달해 정책 브리핑을 생성하고, RAG로 질의응답한다.

Scope — 포함

  • 공공데이터 기반 위험도 예측
  • 정적 위험지도 + 기상 조건별 위험도
  • 정책 브리핑 + RAG 챗봇

Scope — 제외 (후속 확장)

  • CCTV 실시간 객체 탐지
  • 실시간 알림 / 신호 연동
  • 현장 IoT 센서 연계

04 베이스라인 모델 — 설계 결정

희소 이벤트를 어떻게 학습하고 평가할 것인가

로드킬은 전체 구간 대비 발생 비율이 낮은 희소 이벤트다. 세 가지 결정 기준으로 누수와 낙관 편향을 피했다. 합성 데이터로 전체 흐름(로딩→분할→전처리→학습→평가→SHAP)을 검증했다.

불균형 처리

클래스 가중치

class_weight="balanced_subsample" / scale_pos_weight

오버샘플링(SMOTE)은 CV 폴드마다 학습 데이터로만 재계산해야 누수를 피할 수 있어 구현이 번거롭다. 가중치 방식은 누수 위험이 없고 단순하다.

평가 지표

PR-AUC 중심

average_precision + F1-최적 임계값

음성이 압도적으로 많으면 ROC-AUC가 낙관적으로 나온다. 분류 임계값도 고정 0.5 대신 F1을 최대화하는 지점을 탐색한다.

분할 전략

Spatial split 기본값

StratifiedGroupKFold(segment_id)

같은 구간의 다른 날짜가 학습·평가에 동시에 들어가면 공간 정보가 누수된다. 미래 예측력 검증 시에는 --split temporal 옵션 사용.

SHAP(interpret.py) 변수 기여도는 4단계 정책 브리핑의 근거 자료로 그대로 재사용 tests/test_baseline_pipeline.py — 전체 흐름 통과
05 Streamlit 대시보드

목업 데이터로 UI 뼈대부터 먼저 검증

전처리·베이스라인 실데이터 학습을 기다리지 않고, 합성 구간 데이터로 지도·필터· KPI·구간 상세·챗봇 UI를 먼저 만들어 AppTest로 헤드리스 검증까지 마쳤다.

01
필터 · KPI

도로 등급 / 최소 위험도 슬라이더, 전체·표시 구간 수, 고위험 구간 수, 평균 위험도.

02
위험구간 지도

pydeck 기반, 위험도 4단계(안전·주의·위험·매우위험) 색상 구분, 클릭 선택 지원.

03
구간 상세 패널

선택한 구간의 위험도 근거와 정책 브리핑이 표시되는 영역 (LLM 연동 전).

04
위험구간 챗봇

현재는 키워드 매칭 기반 목업 응답. RAG·Claude API 연동 예정.

⚠ 화면의 도로·좌표·위험도·브리핑·챗봇 응답은 전부 합성 데이터입니다. 실제 브라우저에서의 지도 클릭 인터랙션은 아직 직접 확인 전입니다.
data_provider.py — load_segments() 하나만 교체하면 실제 데이터로 전환 streamlit run src/dashboard/app.py
